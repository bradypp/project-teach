# Project mission

## Why

Use Switchboard, a fictional incident-investigation agent, to learn where applied AI engineering meets platform engineering. Build toward an explanation that can be traced to evidence and a job that behaves predictably when components fail.

## Success looks like

- Explain which state belongs to the Go API, worker and LangGraph investigation.
- Trace a runbook source from retrieval into the model input and a final citation.
- Choose a context budget and explain what is omitted.
- Design an evaluation that identifies the failing stage instead of producing only a headline score.
- Reason through a lost client response, worker lease expiry and an insufficient-evidence result.

## Constraints and scope

- Synthetic teaching example; no learner achievements or working backend are implied.
- Read-only tools and tenant-scoped evidence. Production mutation is out of scope.
- The initial lessons explain established mechanisms; later recovery lessons cite source documentation.
- Track the notebook alongside the example project and use the baseline teaching style.
