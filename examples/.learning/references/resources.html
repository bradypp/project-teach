Sources for reliable delivery

Created 14th Sept 2026 · 02:40

Primary sources for Lantern’s delivery contract, retry identity and bounded queues. Return to these when implementing or checking the linked behaviour.

  • RFC 9110, §15.3.3: 202 Accepted — defines the deliberately noncommittal meaning of 202 Accepted.
  • Stripe webhook documentation — a concrete provider contract covering fast 2xx responses, repeated deliveries, asynchronous handling and event IDs.
  • Making retries safe with idempotent APIs — explains caller-provided request identity, atomic recording and the same-ID/different-intent edge case.
  • SQLite UPSERT and transactions — authoritative behavior for uniqueness conflicts and commit boundaries in Lantern's storage layer.
  • Python asyncio queues — exact maxsize and blocking semantics for the in-process handoff example.
  • AWS Well-Architected: fail fast and limit queues — operational guidance on bounded backlogs, message age and overload.

Apply these sources with the reliability checklist and the current delivery model.
