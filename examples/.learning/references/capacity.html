Capacity at a glance

Created 12th Sept 2026 · 18:11

Fieldnotes export service · fictional learning project

Use this while deciding whether the export service should accept another job. The numbers below are illustrative, not measurements.

A small capacity model

For an interval of length t, estimate the change in pending work as (arrival rate − completion rate) × t, while work remains queued. Clamp the pending count at zero. This model ignores job-size variation, failures and changes in concurrency.

Quiet2/s5/sStays empty after prior work drains

When the queue is full

  • Wait: the producer waits for room. Useful when the caller can tolerate that wait.
  • Reject: return an explicit temporary refusal. Useful when acceptance must remain quick.
  • Drop or replace: appropriate only when the product permits losing or superseding that work; not the proposed export contract.
  • Add capacity: useful only if the constrained dependency can actually support more concurrent work.

Observe before tuning

  • Age of the oldest pending job: how long has someone waited?
  • Completion rate and duration distribution: are a few huge exports dominating?
  • Rejections and retry attempts: how much work is arriving beyond fresh submissions?
  • Failures by cause: are retries addressing recoverable failures or repeating invalid requests?
