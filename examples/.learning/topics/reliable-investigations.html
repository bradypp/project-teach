A reliable investigation, end to end

Created 16th Sept 2026 · 21:44

An investigation can fail before the model sees the evidence, while it reasons, or after it finishes. Connect the lessons by following one accepted job through those stages.

Follow the job and its evidence

After the API accepts a job, the job store tracks its owner and deadline. The graph records gathered evidence and the next step. The saved answer links claims to sources. Keeping those records distinct lets you ask a precise debugging question: did the worker lose ownership, did the source miss the prompt, or did the answer misread it?

Decisions for the first version

  • Use read-only deployment and runbook tools. Keep permissions in the tool service.
  • Persist jobs before acknowledging them; make request keys tenant-scoped.
  • Record candidate IDs separately from packed evidence IDs.
  • Require citations and allow an explicit insufficient-evidence outcome.
  • Evaluate each boundary before spending time on a more elaborate agent loop.

The costs are additional state, a worker process and a test corpus to maintain. A single synchronous RAG call is easier to build and may be sufficient for a smaller product. This project deliberately explores the point where recovery and conditional tool use justify the extra machinery.

Read around the next decision

  • Where the agent ends and the platform begins — ownership, leases and deadlines.
  • Retrieve evidence before writing the answer — candidate selection and context budgets.
  • An eval should tell you what broke — isolate a failure before tuning a prompt.

Work through recovery next

A retry raises two different questions: may this worker still write, and will repeated work use the same evidence? Start with leases, deadlines and cancellation for the first, then replay and source versions for the second. The research comparison separates documented framework behaviour from the proposed job protocol.

Before implementation, pin the dependencies and test the races. The notebook contains design examples and synthetic cases, not a deployed backend or results from fault-injection tests.
