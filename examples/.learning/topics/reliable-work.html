Reliable work

Created 12th Sept 2026 · 18:11

Fieldnotes export service · fictional learning project

Accepting a job, executing an attempt and publishing a result are separate events. A reliable export service defines what happens between them.

Current synthesis

  • Capacity governs whether we should accept more work.
  • Identity governs whether two requests mean one export or two.
  • Recovery governs what a new worker may safely do after the previous one disappears.

How the ideas connect

Retries add attempts to the workload. A capacity plan that counts only fresh user requests may underestimate the work. Conversely, rejecting a saturated request needs an explicit client response; an immediate endless retry would simply add pressure.

For the learning prototype, use the bounded-queue experiment to expose saturation before selecting infrastructure. For durable acceptance, investigate storage and claiming as a separate decision. This keeps the first experiment small while keeping the missing guarantee visible.
