Answer: what subject was taught or applied, and how should it shape future teaching?

Read [writing guidance](../teach/references/writing.md) before maintaining Markdown or explaining an update.

## Find the evidence

- Read [project context and records](../teach/references/learning-system.md), which owns the evidence boundaries and record criteria.
- Inspect the supplied account or recent accessible conversation, new lesson, related completed plan, ticket or implementation, and existing records.
- A created lesson counts as learning undertaken for its purpose. Completed project work counts as application of relevant subjects, including agent-assisted work; neither alone proves personal mastery.
- Preserve the learner's actual contribution when they explain, predict, report study or correct an earlier idea. If no useful learning account or artifact is available, ask for a short account rather than inventing history.

## Reconcile

Run after teaching and reviews, when responses or study are discussed, and after related plan, ticket or implementation completion. For a new quiz, reconcile useful links and vocabulary. Browser actions leave reconciliation to the next conversation with the learner.

1. Identify the subjects taught, applied or explained. Find related records by concept and aliases before writing.
2. Create or enrich a record for each meaningful lesson subject, linking the lesson and noting its purpose. Add completed work to the same subject record as **applied in the project** with a work link. Keep learner reasoning and self-report distinct from these events. Preserve useful uncertainty.
3. Reconcile the thin `LEARNING_STATE.md` summary of taught, applied or explained subjects and any affected deferred topics or opportunities.
4. For a created lesson, add or refine useful reusable terms and lesson links in the same run, creating the default glossary on demand when needed. Reconcile other affected glossary terms, resource collections and reciprocal links using [collection maintenance](../teach/references/learning-system.md#reference-collections); preserve mandatory tags and deduplicate across category pages.
5. Create or revise a topic synthesis when accumulated material warrants it, following [topic guidance](../teach/references/learning-system.md#topic-synthesis). Keep the explanation current while retaining learning history in records.
6. When changing HTML pages, links, IDs or metadata, complete [artifact maintenance and verification](../teach/references/artifacts.md#maintain-and-verify). Confirm unresolved changes to the mission or user-stated goals; preserve authorised choices and manual content.

Research claims or synthesis needing verification using [research guidance](../teach/references/research.md). Report what changed and what the evidence supports, or why no change was needed. This workflow reconciles learning; it does not primarily teach.
